## Friday device pass

Run on the web build in a phone-sized browser (Chromium, touch on): 390 × 844
(iPhone), 320 × 640 (small Android) and a slow connection (~1.6 Mbps, 300 ms
latency). Full flow each time: search → results → fare → traveller → seat →
payment (card) → booked. No errors, nothing wider than the screen.

Fixed:

- **Date cut off on small phones.** At 320 px the Depart field showed
  "10/02/202". Depart / Return / Passengers now sit side by side when there's
  room and stack when there isn't.
- **Passenger − / + were 24 px.** Now 34 px with extra touch slop; the box
  keeps its height.
- **Seats were 28 px.** Now 34 px (38 px on tablets) with a larger letter; six
  seats, the aisle and the row number still fit a 320 px screen.
- **"Flight details" was a 30 px strip.** Now a ~42 px tap area.
- **Stops filter read "Any number of st…".** Now "Any stops".

Measured, not fixed yet:

- **First load of the web app on a slow connection: ~6 s.** The JavaScript is
  2.4 MB (580 KB compressed) and five Poppins weights (~750 KB) load before
  the first screen draws. Doesn't affect the phone app (fonts are bundled).
  Next step if the web version matters: preload/subset the fonts and show the
  splash screen while they load.

Not covered by a browser (needs a real phone, see `docs/device-testing.md`):
the keyboard covering fields, notch / home-indicator safe areas, real Wi-Fi
off and slow networks in Expo Go.
